# Current Strong training binding — staging source

This directory supplies deterministic materialization for the existing Strong POST decision and the existing Generic Training executor. It contains no provider client, optimizer, environment runner, or human scientific selection. A passing fixture is not a training execution or Max-10 release.

`recipe_context` needs only `dataset_sha256` and `row_count`. Optional explicitly registered seed constraints may be supplied; otherwise Strong chooses both seeds. The existing formal executor requires equal training/data seeds and micro-batch 1. Generic V2 `contracts.py:393-395` forbids a partial final accumulation group; no new divisibility gate was invented. Epochs, accumulation, learning rate, weight decay, clipping, warmup and seeds have no numeric fallback. Native steps and token budget are derived from current rows and the chosen recipe.

NO_TRAIN accepts a null recipe with no dataset context. It cannot enter the training materializer. This implementation does not reinterpret or change the native POST verdict or the verifier's effect label.

## Verification and live integration

`python -m pytest work/v17/entry/tests/test_training_job.py work/v17/training_binding/tests work/v17/post_binding/tests -q` passed **86 tests** (11 scheduler tests, 55 training-binding tests and 20 POST-binding tests). The native PRE integration runs the real dynamic finalizer/schema and logical/attempt artifacts, verifies same-call recovery, then detaches the original PRE directory and reads the complete captured evidence. Regression tests also validate native LF-sealed historical H4.4 plan/verifier/branch objects from `server_canary_paired_03`, and use the SHA-verified original server `formal_train.py` from `server_training_sources_04` for actual order and manifest builders. Software adapter weights are explicitly synthetic. Tests do not initialize a model, call a provider, submit Slurm, execute an optimizer or prove a production round.

The functions are connected to `live_adapter/pre_stage.py` and `h44_input.py`: the same PRE schema/prompt is extended, the original native accepted artifact remains unchanged, raw request/response and attempt identity are adopted, and `pre_root/PRE_STRATEGY_RECEIPT.json` plus `PRE_STRATEGY_CAPTURE_BINDING.json` provide a typed self-contained capture. Stage6AN source bytes are verified against the exact registered Git objects before use. Root-owned `post_binding/context.py` and the H4.4 worker consume this capture, the current runtime tokenizer and verifier; `entry/training.py` consumes their dataset and same-POST receipt.

The current clean runtime context is derived automatically from the H4.4 plan's exact runtime bytes and current request. The training source registration seals the finite Generic/clean/profile/canonical source set, V1.11 dual-view delegate and installed binding modules. Real first-parent initialization retains all original zero-step checks. Subsequent rounds compare the promoted current runtime with the previous accepted adapter and retain its trained weights; they do not repeat clean initialization. Completed native training can be adopted after a result-publication interruption. Started or failed optimizer attempts cannot be blindly rerun. GPU execution and a new production round still require their actual server receipts; this local test suite does not supply them.

The scheduler reuses original `submit_once` with distinct `smoke` and `training` phases and the original registered 20-minute allocation for each. It does not combine their wall-clock allowance or modify the Strong-selected recipe. Initialization results have `training_execution_count=0` and `optimizer_executed=false`; only a native accepted training terminal counts as training. The training path uses `NativeClean.execute(adopt_only=True)`, which has no call to the smoke execution body. CPU adoption can recover a completed initialization receipt or an already written native training result without another job. Registered wall-clock limits remain operational limits; epochs are never shortened automatically to fit them.

Stage6AN requires nine strategy content fields plus a content SHA and independent verification provenance. It does not require a JSON file to have existed before F0/F1. The implemented route freezes the representation in the existing PRE response, so no post-outcome field synthesis is needed. The original native candidate projector explicitly identifies the first option action as executable at the source state (`src/pchsi/analyzer/candidate_projector.py:82-89`), while later actions require live-menu revalidation. The training view uses that initial-state decision only after checking it was actually executed at the same observed state. The F1 causal unit remains the complete option, including its termination condition and all executed intervention steps; verification records `causal_verification_scope=COMPLETE_REGISTERED_OPTION` and `standalone_action_causal_effect_claimed=false`. F1 is not truncated, and the training view makes no claim about the effect of an isolated first action. Full candidate bytes, source context and complete evidence references remain retained. Existing historical PRE calls without the annex cannot acquire new strategy text retroactively.
